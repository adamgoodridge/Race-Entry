### Task 13 — Fix missing foreign-key existence checks in EntryService

### Task 16 — Fix PATCH /entries/{id}/status not removing EntryDriverMaps on cancel
**Status:** Done
**Commit:** fix(task-16): remove EntryDriverMaps when PATCH cancels an entry

PRD section 3 states: "Cancelling an entry removes all associated EntryDriverMap records." This rule was only enforced through the mediator's `cancel()` method (called during owner-deletion cascade). `PATCH /entries/{id}/status` with `CANCELLED` called `updateStatus()`, which changed the status but left EntryDriverMap rows behind — a direct PRD violation.

Changes:
- `entry/EntryService.java` — added `@Transactional` to `updateStatus()`; when `newStatus == CANCELLED`, calls `entryDriverRepository.deleteByEntryId(entryId)` before saving the status change
- `RaceEntryIntegrationTest.java` — 1 new test: create entry with an assigned driver, PATCH to CANCELLED, verify GET /entries/{id}/drivers returns an empty list

All 33 integration tests pass.

### Task 18 — Fix removeDriver to validate entry existence before checking assignment
**Status:** Done
**Commit:** fix(task-18): validate entry existence in removeDriver before checking assignment

`assignDriver()` calls `findById(entryId)` at the start, returning "Entry not found: X" → 404 for unknown entries. `removeDriver()` did not — it queried `entryDriverRepository.findDriverIdsByEntryId(entryId)` first, which returns `[]` for a non-existent entry, then threw "Driver X is not assigned to entry Y" → 404 with a misleading message.

- `RaceEntryIntegrationTest.java` — 1 new test: `DELETE /entries/99999/drivers/{id}` → 404 with message containing "Entry not found"
