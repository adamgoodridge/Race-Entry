### Task 4 — Create RacingEventMediator
**Status:** Done
**Commit:** feat(task-4): create RacingEventMediator with owner deletion cascade

- `mediator/RacingEventMediator.java` — @Component, @Transactional deleteOwner()
- Cascade sequence: for each boat owned → cancel all ACTIVE entries (EntryService.cancel removes EntryDriverMaps) → markOrphaned → then delete owner record
- No business logic in the mediator; all rules enforced by BoatService, EntryService, OwnerService

### Task 6 — Create REST controllers
**Status:** Done
**Commit:** feat(task-6): create five REST controllers per PRD section 5

- `owner/OwnerController.java` — POST /owners (201), DELETE /owners/{id} (204) via RacingEventMediator
- `boat/BoatController.java` — POST /boats (201), GET /boats?ownerId={id}
- `event/EventController.java` — POST /events (201), GET /events (uses EventRepository directly — no service needed for pure CRUD)
- `entry/EntryController.java` — POST /entries (201), GET /entries?eventId={id} or ?boatId={id}, PATCH /entries/{id}/status (returns updated entry)
- `driver/DriverController.java` — POST /drivers (201), POST /entries/{id}/drivers (201), DELETE /entries/{id}/drivers/{driverId} (204), GET /entries/{id}/drivers

Each controller uses inner static request classes for @RequestBody deserialization. DriverController injects EntryDriverRepository + DriverRepository directly for the driver-list read path (no service-layer business logic there).
